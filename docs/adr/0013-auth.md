# 13. Auth: rules in git, credentials on the Pi

- Status: Accepted
- Date: 2026-05-28, ownership split 2026-08-19

## Context

Anyone on the Pi's Wi-Fi can reach the UI, visitors included. Settings, calibration and firmware must be admin-only. The karaoke kiosk and the local daemons have to work without logging in. It is a local art installation on a private network with nothing worth stealing, and it has to update unattended.

## Decision

- A JWT in an HTTP-only cookie, valid 7 days. Passwords hashed with argon2 (bcrypt broke on Python 3.13, `98f924b`). The signing secret is generated on the Pi and kept in `.secret_key` (`15ea5ba`).
- Roles, per-endpoint rules and per-page rules live in `sparkles-api/auth_config.yaml`, first match wins. Plain passwords in that file are hashed on first start.
- Access rules belong to git, credentials belong to the Pi. `update.sh` and `push_to_pi.sh` set the live `users:` block aside and merge it back after a pull.
- A short list of public paths: login, `/karaoke`, `/keyboard/`, plus `/internal/*` and `/getMidiParams` for local daemons. A 401 on `/getMidiParams` used to make aubio silently fall back to its compiled-in defaults.
- Hardcoded secrets in the deploy and setup scripts are deliberate: the Pi's sudo password, NOPASSWD sudo for the service user, Wi-Fi passwords. "local installation, update must run unattended".

## Consequences

- The repo is public, so those credentials are public. Accepted.
- Every new endpoint needs a rule, or it falls through to the `*` default (admin and user).
- Anything that fetches without a browser session, a daemon or an ESP32, needs a public path.
